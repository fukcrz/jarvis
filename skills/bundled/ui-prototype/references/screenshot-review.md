# 截图检查

只检查指定 PNG。不改代码、不 git、不靠猜看不到的交互。

## 何时截

- 全量：新铺一批页面、用户要求检查、收口验收
- 主题修复：只重截相关页
- 不要每个小改动全量截

走 `playwright-browser` skill。产物放到当前项目 `.tmp-*`（gitignore 的临时目录），不进 git。用 `read` 看图，不要把整页 PNG 塞进对话。

默认视口：后台桌面 `1440×900`；用户端 H5 `390×844`。参考图/产品是手机后台时再截一档窄屏（约 `390×844`）。等网络空闲后再截；弹层用非 full-page，避免把遮罩外的页面拉进来。

## 忽略

- 后台侧栏底部菜单被视口裁切
- Playwright `fullPage` 把 `position: fixed` 的侧栏/抽屉/tabbar 画进页面中间：改截图方式，不改布局
- 脚本采错页、没带路由参数拍成空白新增：先修脚本
- 空数据本身；演示数据日期过期但筛选逻辑正确
- 截图里看不到的交互（不要猜点击后会发生什么）
- 按钮源码有 handler 时，不要笼统记成「假按钮」；看起来能点却不跳/不生效的另记

## 要记

视觉 / 布局 / 样式 / 功能缺失 / 业务口径冲突 / 文案。主色跟项目主题。UI 文案只允许标注、状态、不可逆后果。空状态要「现状 + 下一步」。自定义底栏弹窗：有 tabbar 的 H5 才加底栏间距，不要误判小程序。

每条问题必须能指出截图位置。短、具体。先前标过已修、截图仍在的，按复发重开，不要靠记忆。

## 去重

逐页稿只当证据。执行以去重工单为准，不要维护第二份状态。

工单字段：严重度、端、页面、现象、建议、验收。状态：`待处理` `进行中` `已验收` `不做`。

```text
P0 阻断 → 共性组件 → 其余 P1 → P2 跟随提交
```

复验新问题加一条工单，不要再写 N 份逐页报告。

## 逐页稿模板

```markdown
# {文件名不含扩展名} 检查结果

- 数据状态：{空/有数据/抽屉/弹窗/未登录等}
- 检查时间：{日期}

## 总体判断

3–5 句。
```
