# 空 / 失败 / 未登录

每张业务页至少能看出三种：有数据、空、失败。需要登录才能看资产的页再加未登录。

## 空

空数据本身不是缺陷。缺陷是：整片空白、无筛选写成「暂无匹配」、只报「暂无」却没有下一步。

句式：现状 + 下一步。整句 ≤ 30 字。

- 无筛选：`暂无门店，去新增`
- 有筛选：`暂无匹配，改条件`
- 无方案仍有主按钮：空态说明 + 按钮禁用并改文案，不要白屏可点

抽共用空态组件。后台表格用空槽，不要让主工作区高度为 0。

空态图标用静态插画，不要用看起来像 loading 的字形（如 `◌`）。

同一动作只留一个入口：空态按钮和底栏主按钮不要同时「新增/上传」。无数据时只留空态；有数据再出底栏主按钮。

有 tabbar 时，空态 CTA 必须完整露在底栏上方，点得到。优先用 `view` 当按钮；`uni-button` 的默认高度/边距容易把按钮顶进底栏。

## 失败

接口失败不能画成空列表。独立失败态：现在什么情况 + 重试/返回。

toast 映射成用户能懂的一句。禁止 URL、字段名、堆栈、接口原文。

## 未登录 / 游客

跟产品。两种常见口径不要混：

- **登录墙**：资产、订单、卡券页只留登录入口。不要假筛选、假 `0`、未登录订单 Tab。
- **游客可逛**：目录/详情可看；点下单、开门、个人资产再拦登录。拦完回到原目标，不要把人丢回首页登录卡。

登录成功必须离开登录页。首次资料完善可以跳过时，跳过项不要同时显示「未完成」和「成功」。

登录/提交加锁，防连点。

## 加载

有明确加载态。不要用空列表冒充还在请求。

- 首次进入：可以全屏 loading / 骨架。
- `onShow`、Tab 切回、浏览器返回：保留已有内容，静默拉新。不要每次把页面打回全屏 loading。
- 失败时保留旧数据，给重试；不要清空列表再画空态。

## 弹层 / 抽屉

固定底栏必须给内容区留避让，滚到底能看见最后一组字段和按钮，不重叠。确认清单在主按钮之上；未完成时主按钮不可用。

## 文案边界

常驻区禁止功能简介、字段 helper、复述标题、营销腔。教程/验券指引可留短步骤，仍禁止简介和后台投放位置。确认弹窗是后果说明的唯一载体。

产品基线要求留下的不要用文案规则一刀切：登录协议勾选、结果页免责。营销句、页面简介仍删。和产品说明书冲突时先问。

开发字段（OpenID、内部 ID）不进用户主界面。封面/图片加载失败用占位图，不要灰底空播放钮。
