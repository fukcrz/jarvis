# 去 AI 味 / 内容优先

原型要像真实产品，不要像演示稿或模板市场 landing。

优先级：去 AI 味 → 可用性 → 视觉。好看不能压过任务和信息。

## 先内容后布局

铺页前先能回答：

- 谁来
- 来干什么
- 最重要的信息是什么
- 主操作 / 次操作
- 哪些可以折叠或弱化

禁止先画好看区块再往里塞字。没有业务意义的 hero、feature grid、卡片套卡片、顶部说明堆砌，直接不画。

## 禁止的套路

- 空洞大标题、泛泛副标题、价值宣言
- 无意义功能卡片、为填页面加的区块
- 大面积渐变、玻璃拟态、霓虹、过度阴影
- 随机图标、随机徽章、随机颜色
- 英文装饰 eyebrow（`MONDAY, JANUARY 12` 这类）
- 巨大按钮制造假重点；一页多个主按钮
- 装饰性 `›` / 图标看起来像进入下一级，实际只选中或不跳转
- 桌面不该出现的汉堡/关闭，或点了也不工作的壳控件

主按钮只给当前页最重要的那一个。次要操作弱化。危险操作把风险做清楚。非删除（下架/隐藏）不要用删除红和图标。

## 克制

层级靠排版和间距，不靠颜色堆砌。8pt 间距。每页字号种类收住。中性色打底，品牌色只给关键操作和身份。

动效只表达状态变化：快、小、可预测。不要弹跳、长过渡、夸张入场。参考图写明了扫描钮缩放、加载窗之类，按参考还原，不要自行加一套。

不确定时删装饰，留结构、内容和功能。

## 好用

- 触控目标够大（移动端按约 44px 估）
- 不要靠 hover 才能发现的信息和操作
- 占位符不替代表单标签
- 桌面可以用表；窄屏改卡片 / 分组行，不要把宽表塞进手机
- 弹窗只承载短流程；移动端优先底弹层或全屏
- 空表单一进来不要满屏红校验，点提交再提示；禁用按钮必须看得出不能点
- 数字图单点不要画成无线的空坐标；点数不够就走空态或画锚点
- 无姓名/无生日不要拼出空白或 `/ 0 岁`，用「—」
- 后台默认按桌面效率做。产品/参考图是手机后台时，单独做抽屉导航和窄屏列表，禁止把桌面表缩小当适配
