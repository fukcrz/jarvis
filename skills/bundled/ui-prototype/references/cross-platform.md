# 跨端核验

H5 布局必须以运行时 DOM、计算样式、元素边界为依据。不要用模板标签猜运行时标签。

## uni-app H5

模板里的 `<button>` 渲染为 `uni-button`。查按钮对齐、高度、默认边距时，同时核对框架默认样式和自定义选择器优先级。空态/卡片里的主操作优先用 `view`，避免默认 `uni-button` 把 CTA 顶进 tabbar。改全局重置或共用组件后，在目标视口复核关键对齐，确认有意居中的没有被带偏。

## 标题栏

以参考图为准，不要整站一刀切。

- 顶部有微信胶囊（右上 `··· ○`），标题栏与状态栏同底，内容不从屏顶开始 → 系统导航栏。小程序 `pages.json` 不写 `navigationStyle: custom`，页面内不自绘标题栏，返回由系统提供。
- 页面背景延伸到状态栏，返回箭头由页面自绘 → 自定义导航栏。

两者都像时跟参考图。看不出时默认自定义。

## 自定义底部弹窗

只在 **tabbar 页**处理跨端差异。

- 小程序原生 tabbar 不占页面内容空间：弹窗按页面底部定位，不额外加底间距。
- H5 底栏占页面空间：优先相对 `page` 容器定位；无法统一时，仅 H5 加与底栏对应的避让。
- 禁止把 H5 底间距无条件套到小程序，否则小程序弹窗和页面底之间会多一条缝。
- 非 tabbar 页两端都没有底栏，用同一套底部定位和间距。

## 后台 Web

不是小程序。侧栏当前页必须有选中态；菜单里根本没有当前页仍算问题。抽屉/弹窗固定底栏不要挡住表单。统计卡铺满工作区宽度，不要右侧一条空灰带。

默认按桌面效率做（约 1024px 及以上）。产品/参考图是手机后台时：抽屉导航、窄屏列表/卡片、移动表单，单独验收窄屏；禁止把桌面宽表缩小当适配。
