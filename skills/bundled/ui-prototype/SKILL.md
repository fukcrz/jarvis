# ui-prototype —— 高保真可点击原型

目标是代码里的高保真还原，不是示意页、不是接正式 API、不是 Figma。信息层级、布局、组件、状态、交互尽量贴近参考；主题色按**当前项目**系统性替换。

项目 `AGENTS.md` 有主题色、导航、tabbar 特例时以项目为准。决策未定时先问，不要猜。

需要细节时再读：

- [空 / 失败 / 未登录](references/states.md)
- [去 AI 味 / 内容优先](references/visual.md)
- [截图检查](references/screenshot-review.md)
- [跨端核验](references/cross-platform.md)

## 不做

- 接正式 API、伪造写入成功、用 mock 冒充已落库
- 画 Figma / 设计稿文件
- 调 `gen` 生图（原型图网上找）
- 生成图标 / favicon / tabbar 图标（现成资源；[Iconify](https://icon-sets.iconify.design/) 只是参考）
- 每个小改动全量截 100+ 页

未接正式 API 的模块也按原型做完视觉、布局、交互、截图能看出的逻辑。点保存若无契约：toast「原型交互，数据暂未写入」，界面可本地变，不假装正式成功。

## 铁律

1. **文案**：界面只留标注、状态、不可逆后果。默认零文案。介绍/讲解/helper/营销腔 → 删。拿不准就删。
2. **内容先于布局**：先定用户、任务、主信息、主操作，再铺区块。去 AI 味，见 [visual.md](references/visual.md)。
3. **空态**：「现状 + 下一步」。无筛选禁止「暂无匹配」。空数据本身不是缺陷。
4. **失败**：独立失败态 + 人话 toast。失败 ≠ 空列表。界面禁止 URL、字段名、堆栈。
5. **未登录**：跟产品/参考图。登录墙页只留入口、不要假资产；游客可逛的页不要混进假数字。见 [states.md](references/states.md)。
6. **刷新不闪屏**：首次可全屏 loading；`onShow`/返回刷新保留已有内容，静默拉新。失败保留旧数据。
7. **素材**：位图用网上图填充；图标用现成资源。产品期真素材才用 `gen`。
8. **一次一主题**：原子提交。改完只重截相关页。
9. **校验**：能不写就不写。少处写、从宽；界面不让填的接口不准要。见全局 `AGENTS.md`。

## 阶段

小改动从当前阶段切入，不要从头重跑。新项目或大铺页按序走。先调查再方案，用户说「直接做」除外。

```text
对齐参考 → 铺壳 → mock → 逐页还原 → 补状态 → 按需截图验收 → 按主题修
```

### 1. 对齐参考

读参考图 / 模板小程序 / 说明书（以项目指定的产品基线为准）。列出页面地图：路由、Tab、抽屉/弹层、未登录变体。仓库里有整页参考 PNG（`参考/`、`素材/` 等）时，优先按图还原底栏形态、加载窗、主按钮位置，不要改成「差不多的现代风」。

每页判定：

- **导航栏**：参考图有微信胶囊、标题栏与状态栏同底、内容不从屏顶开始 → 系统导航栏。背景延伸到状态栏、返回箭头自绘 → 自定义导航栏。看不出时默认自定义。
- **tabbar**：哪些页有底栏。自定义底弹窗的跨端差异只发生在这些页。
- **主色**：参考原色按项目主题替换，保持对比度。

### 2. 铺壳

先 token 和骨架，再铺业务页。

- 颜色 / 圆角 / 字号 / 页面底写入主题变量，不要每页写死另一套主色
- 共用：标题栏、空态、失败态、卡片、状态点、图标封装
- 后台：侧栏当前页必须能看出来（高亮；允许滚动后看到）
- 后台默认桌面。参考图/产品是手机后台时，抽屉导航 + 窄屏列表，不要把宽表缩小当适配
- 配置类页面：中文字段表单，JSON 不进界面

### 3. mock

静态列表 + 必要的本地可写 store。类型和字段名贴近产品对象，不要为演示编一套对不上的结构。

覆盖：有数据、空、加载、失败、未登录/游客、关键弹层。不要用空数据偷工减料，也不要把失败画成空。

### 4. 逐页还原

对照参考图做信息层级、间距、组件形态、主操作位置。先做无解释文案版。没有参考图时从真实任务长出来，不要套 landing 模板。

标题和格子里的数必须同一口径：「今日」不要塞历史值。占位符不要写成「选填」却在保存时要求必填。

破坏性操作一律确认弹窗，只写不可恢复与影响范围。零值不用增长绿/告警红；无数据比率用「—」，不用 `0.0%`。

### 5. 补状态

每张业务页至少能看出：有数据、空、失败。登录墙页再加未登录。清单见 [states.md](references/states.md)。

### 6. 按需截图验收

全量截图只在：新铺一批页面、用户要求检查、或收口验收。修一个主题只重截相关页。

截图走 `playwright-browser` skill，存项目 `.tmp-*`（忽略、不进 git），用 `read` 看 PNG。不要把整页截图塞进对话。

默认视口：后台桌面 `1440×900`；用户端 H5 `390×844`。手机后台再加一档窄屏。只记截图能确认的问题；侧栏底边被视口裁切当伪影，不修。流程和模板见 [screenshot-review.md](references/screenshot-review.md)。

### 7. 按主题修

```text
P0 阻断 → 共性组件 → 其余 P1 → P2 能跟提交就带上
```

去重成工单，不要按截图各写一份进度。状态：`待处理` → `进行中` → `已验收`；误报标 `不做` 并写原因。每做完一个主题：重截相关页，对照验收再勾。
