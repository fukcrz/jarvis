# 浏览器联调

普通打开网页、登录、截图：直接用 Playwright。

联调：委派 `browser-qa` 子代理。主代理不要自己点，不要写爬页脚本。过程不要写进对用户的长回复，只交报告。

## 先收齐再派

缺的问，能从环境/仓库推断的不问。没齐就不要派。

### 测什么

必须指定其一，不要默认全部：

- 某个功能模块
- 全部
- 只测用户端
- 某个页面

单位是**任务**（预约一单、储值、开门），不是路由。「全部」= 各角色主路径都做一遍。

全量还要有：每个端的入口 URL、怎么登录、默认城市（若有）。用户端和后台是两条任务线。

### 能碰什么

| 项 | 默认（开发联调） | 必须问 |
|---|---|---|
| 环境 | 开发 | 演示给客户看、或像生产 |
| UI | 任务需要的才点（含提交、支付、删除确认） | 只看不动 / 可以乱点当探索 |
| 业务数据 | 可下单、储值、改配置 | 只读、不准产生单、不准动别人的数据 |
| 数据库 | 不直接动库 | 只有明确说可以清库/灌数 |
| 外部 | 不真打款、不真发短信；门锁失败记没做成 | 要求走真微信/真短信/真锁 |

「任意操作 UI」不是默认。默认不是乱点，是任务需要才点。

### 委派 prompt 必带

- 测什么
- 环境、UI、业务数据、数据库、外部（写明是用户说的还是默认）
- 入口 URL、登录、城市、仓库路径、报告目录
- 不要改产品代码

子代理用 Playwright 做任务、截图、写 `report.md`。主代理只回收摘要。

## 报告怎么用

摘要必须有五块，可优化不能省：

1. 按什么权限测的
2. 做了哪些任务（做到哪一步）
3. 确认的问题
4. 可优化
5. 没做成的任务和原因

细节用报告路径和截图。不要把点击过程复述给用户。
